# Harness / setup model

Design constraints for how Yardcraft setup orients across editors. Live common workflow: `AGENTS.md` + **`yardcraft-setup`**. VS Code family depth: [`yardcraft-setup/references/vscode-family.md`](../../skills/yardcraft-setup/references/vscode-family.md). Connect/bpy depth: `basilisp-blender` skill.

## Depth budget

VS Code family gets a **progressive-disclosure reference** (prescriptive verified steps). Non-VS-Code: ~5 goal-based lines in the main setup skill, ever. Main skill must not read as “Cursor setup with extras.”

## Non-goals

- No README rewrite or second example chat for harness coverage.
- No Emacs/CIDER/monroe/inf-clojure how-tos — wing means wing.
- No alternate Clojure clients on VS Code family; no Backseat Driver “peers”.
- No renaming of the `basilisp-blender` connect sequence, session keys, or `.vscode/settings.json` contents.
